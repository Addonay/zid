# Git backend integration

`src/git/root.zig` is standalone and has no rendering dependency. It uses the installed Git executable and accepts an explicit `std.Io` for every operation. Import the module from the app/build integration; it is not wired into the app yet.

* `Repository.discover(allocator, io, directory, options)` discovers the containing worktree, returning an owned absolute root. `repo.deinit(allocator)` releases it. A non-repository, bare repository, or failed Git invocation reports `error.GitFailed`.
* `repo.status(allocator, io, options)` returns `Status`; call `status.deinit(allocator)` after consuming entries. Each entry has raw-byte `path`, optional `original_path`, `kind`, and Git porcelain-v2 index/worktree status bytes (`.` means unchanged). Untracked and ignored entries use `?` and `!` respectively. Preserve distinct records for the same path. Paths borrow the result's storage, not the repository.
* `repo.diff(allocator, io, path, .staged or .unstaged, options)` accepts an exact root-relative path as bytes. `diff.text` is Git's unified patch; `diff.hunks` gives 1-based old/new ranges and byte offsets into the patch. A zero count denotes an insertion/deletion boundary; clients must handle that when placing gutters. Call `diff.deinit(allocator)` after use. Binary patches have no text hunks. Untracked content is not included in Git diff; callers should provide their own untracked-file presentation.
* Results own allocations independently of the repository. These APIs are synchronous and suitable for a background task using a thread-safe or task-local allocator and a suitable `std.Io`. Keep the repository and input path alive until the call returns; transfer or dispose results before destroying the allocator. Use the I/O implementation's cancellation mechanism for task cancellation; `std.process.run` kills and reaps its direct child on error/cancellation. Options bound stdout and stderr independently and accept an I/O timeout. `StreamTooLong`, cancellation, timeout and spawn failures propagate; nonzero exit is `GitFailed`. stderr is bounded but currently discarded.

Arguments are passed directly, never through a shell. `--literal-pathspecs` prevents metacharacters in names from selecting other paths. Git status uses `--porcelain=v2 -z` and includes all untracked files. Paths on POSIX are arbitrary non-NUL bytes and are not decoded as UTF-8; UI rendering must escape invalid bytes without changing the bytes passed back. Windows process and filesystem encoding restrictions apply. The output cap means very large statuses and diffs fail rather than silently truncate. No file watcher, cache, Git mutations, staged/unstaged untracked patch synthesis, word diff, submodule expansion, or editor wiring is implemented. Git config, attributes, repository state, and installed Git version can affect output. Discovery consumes Git's newline-terminated `rev-parse` output; paths ending in newline cannot be reliably distinguished on platforms/Git versions that quote or otherwise transform it.

Zed reference: `.ref/zed/crates/git/src/repository.rs` exposes repository operations independently of UI, executes status on an executor and checks command success; `status.rs` models per-path index/worktree state. This backend adopts those boundaries while retaining raw NUL-delimited paths instead of decoding lossily, and uses porcelain v2. Unlike the reference's deduplication, duplicate paths remain available to the caller.
