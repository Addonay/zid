# LSP implementation status

`src/lsp` is an incomplete LSP client. The app starts ZLS on demand for an eligible Zig document. It uses explicit `std.Io`, spawns a direct argv without a shell, ignores stderr, and exchanges Content-Length framed messages. Default limits are 8 KiB headers, 8 MiB bodies and 256 outstanding requests. Oversized or malformed frames fail the stream. The decoder callback borrows a frame only for the duration of the call.

`Session` sends initialize, initialized, shutdown, exit, full-text didOpen/didChange/didSave/didClose, completion, hover, definition and formatting requests. The caller must wait for and validate the initialize response, inspect server capabilities and position encoding, and only then send initialized. It must map response IDs to requests and invoke `complete` for every response (including errors). Raw JSON frames, including diagnostics and server requests, are delivered to the caller. `replyToServer` sends the protocol module's default response to a decoded request; call it after `read` returns, while the owned message remains alive. Invalid configuration parameters receive JSON-RPC invalid-params. There is still no automatic dispatcher. Feature responses have not been validated. Full-text changes may not satisfy servers requiring incremental changes.

The synchronous `Session` is single-owner and its `read` blocks. A separate `transport.Worker` owns stdin and stdout on concurrent Io tasks, accepts copied serialized bodies, and exposes bounded inbound and outbound queues. Inbound overflow fails the transport rather than dropping responses; outbound overflow is reported to the caller. Destroy cancels tasks and kills and reaps the process; cleanup can still wait for cancellation or process termination. The caller must keep its allocator and Io thread-safe and alive, and must not race destruction. `Client` uses that transport to initialize, track request IDs, answer server requests, and return owned messages via polling. It is single-owner and has no graceful shutdown policy. Its fake-server test covers initialization, configuration and a correlated feature response.

Position conversion accepts valid UTF-8 and converts to/from UTF-8 byte or UTF-16 code-unit columns, treating LF, CRLF and lone CR as line breaks. It rejects split codepoints, split surrogate pairs and offsets inside CRLF. Conversion scans the input and is not indexed for large files. The app controller maps tracked editor revisions to monotonically increasing LSP document versions.

Zed reference: `.ref/zed/crates/lsp/src/input_handler.rs` separates the background stdout handler from dispatch, correlates responses with pending handlers, and bounds its incoming queue for backpressure. Zid's worker and polling client now provide bounded raw queues and ID correlation, without Zed's full handler architecture.

The app synchronizes up to 32 open Zig documents of at most 1 MiB each, excluding large files and read-only previews. It uses negotiated static sync options and full-document replacement ranges for incremental servers. Snapshots and serialization currently run on the UI thread; server I/O runs in background tasks. Diagnostics appear in the gutter and status bar; the current line's first message appears in the status bar. Versioned results for older revisions are discarded. ZLS 0.17.0 sends unversioned diagnostics even when version support is advertised: these are marked `ZLS ~` and cleared on edit, but a delayed result can still be stale. The app polls at 100 ms while ZLS is running, so idle CPU and latency targets have not been verified. Save notifications can be missed if a document is saved and edited again between polls. Dynamic registration, completion, definition, formatting, automatic restart, and graceful shutdown remain unfinished.

The Zed default `ctrl-k ctrl-i` binding requests hover for the cursor. Results are discarded after document, revision or cursor changes, and Escape dismisses the popup. It displays common LSP hover formats as plain text, up to 8 KiB; Markdown rendering and mouse-triggered hover are not implemented. Wheel scrolling works over the popup. Requests without a server response have no timeout or cancellation and remain pending until shutdown.

An additional temporary probe through `Client` initialized the locally installed ZLS 0.17.0, opened a small Zig document, and received a non-null, non-error hover response. It checked response correlation, not hover content semantics or editor integration; ZLS is not a requirement of the test suite.

A controller probe opened invalid Zig text and received a diagnostic from local ZLS 0.17.0. An isolated X11 runtime check also showed its gutter marker and message, then showed zero diagnostics after replacing the text with valid Zig. This is a narrow manual check, not a comprehensive UI or concurrency test.


A separate `protocol` module parses owned JSON messages, exposes typed publish-diagnostics snapshots, validates integer response IDs, offers a bounded pending-ID tracker, and constructs replies for workspace configuration, workspace folders, and unknown server methods. The caller owns and must deinitialize each parsed message. Workspace configuration currently returns null for each item and workspace folders returns an empty array. The client and transport lifetime limitations above remain. A subprocess echo test verifies framing and transmission of a configuration reply; it does not validate behavior against a language server.
